ESP32 Noise Generator – Multi-Device Home Assistant and Node-RED Integration

1. Architecture

The ESP32 firmware remains responsible for MQTT state and Home Assistant MQTT Discovery. Home Assistant no longer needs a per-device input_select, template sensor, or mode-conversion automation.

Node-RED provides one generic flow for all generators. Device routing is defined in exactly one place: the Device Registry function in `Node-Red/Noise-Generator.json`.

For the current installation the registry contains:
- `hroom` -> `hroom/noise`
- `mbedroom` -> `mbedroom/noise`

To add another generator, add one registry entry and configure the new ESP32 with the matching MQTT base topic and unique MQTT/HA IDs.

2. MQTT Topic Convention

Each generator uses:

`<device>/noise/<state-or-command>`

Current examples:

`hroom/noise/mode`
`hroom/noise/gain`
`hroom/noise/mute`
`hroom/noise/heartbeat`
`hroom/noise/temperature`

and the corresponding `/set` command topics.

The firmware publishes the mode as the friendly text value `White`, `Pink`, `Brown`, or `Blue`. It also accepts numeric mode commands for backward compatibility.

3. ESP32 Configuration

Configure the two generators as follows:

H Room:
- `noisegen-<deviceName>=hroom`
- `noisegen-<deviceName>=hroom`
- `<deviceName>/noise=hroom/noise`

Master Bedroom:
- `noisegen-<deviceName>=mbedroom`
- `noisegen-<deviceName>=mbedroom`
- `<deviceName>/noise=mbedroom/noise`

Use unique Zigbee2MQTT friendly names for the E1810 remotes, for example `NoiseGen_HRoom` and `NoiseGen_MBedroom`.

4. Home Assistant

Enable the MQTT integration. Each ESP32 publishes its own discovery configuration and Home Assistant creates a device containing Mode, Gain, Mute, Online, and Temperature when enabled.

Do not create the old `input_select.noise_gen_mode`, `NoiseGen Mode Friendly`, or per-device mode automations. The discovered Mode entity is already a Home Assistant select with options White, Pink, Brown, and Blue.

The file `HA/noise_generator_package.yaml` is intentionally empty of static entities. It can remain in an existing packages directory without recreating the old per-device configuration.

Because Home Assistant generates entity IDs from MQTT discovery, the supplied dashboard file is a reference rather than a dynamically generated multi-device dashboard. For multiple devices, use the discovered NoiseGen device cards/entities in the Home Assistant UI.

5. Node-RED

Import `Node-Red/Noise-Generator.json`. The flow subscribes to wildcard state topics such as `+/noise/gain`, so the same nodes handle both generators.

The Device Registry is the only device-specific configuration:

```
const devices = {
  hroom: { label: 'H Room', base: 'hroom/noise', remote: 'NoiseGen_HRoom' },
  mbedroom: { label: 'Master Bedroom', base: 'mbedroom/noise', remote: 'NoiseGen_MBedroom' }
};
```

Select the target generator in the Node-RED dashboard. Gain, mode, and mute commands are automatically sent to the selected generator.

The temperature and heartbeat displays are also selected by device. The previous separate temperature flow is no longer required; `Node-Red/Noise-Generator-Temperature.json` is retained only as a migration placeholder.

6. IKEA E1810

The current firmware/Node-RED changes establish the generator routing convention, but E1810 mapping should use the same registry. Each E1810 friendly name should be unique.

When implementing E1810 routing in Node-RED, map the Zigbee2MQTT friendly name to the registry entry's `base` value. Do not duplicate MQTT command nodes for each generator.

7. Adding a Third Generator

Only two places should need configuration:
1. Configure the ESP32 with its unique `noisegen-<deviceName>`, `noisegen-<deviceName>`, and `<deviceName>/noise`.
2. Add one entry to the Node-RED Device Registry.

No new MQTT input/output nodes, mode helpers, or mode conversion automations are required.

8. Optional DS18B20 Temperature

When enabled in the ESP32 firmware, temperature is published at `<<deviceName>/noise>/temperature` and discovered automatically by Home Assistant. The generic Node-RED flow also handles it automatically.

9. Firmware Notes

The firmware publishes MQTT discovery, retained state for mode/gain/mute, heartbeat, and optional temperature. Mode discovery is a Home Assistant select using White/Pink/Brown/Blue.



Firmware device identity
-------------------------
Each ESP32 stores only one persistent identity value: Device Name. The firmware derives the MQTT base topic as <deviceName>/noise, the MQTT client ID as noisegen-<deviceName>, and the Home Assistant unique ID as noisegen-<deviceName>. Set Device Name to hroom on the H Room unit and mbedroom on the Master Bedroom unit. MQTT server/port, credentials, temperature settings, and other independent configuration remain separate NVS settings.
